# rustls 握手入口定位

`RustlsHandshakeLocator` 使用 ELF、既有明文发送入口和已注册的候选片段，输出唯一握手
函数地址、发送字段偏移和调用前置位字段偏移，或明确拒绝。调用前置位字段不自动命名
为 `may_receive`。证书身份布局由 `RustlsConnectionLayout` 独立确认。

## 候选发现与验证

注册前复用函数边界查询器的初始化检查，只读取 ELF 节元数据并取得切片；缺少
`.eh_frame_hdr` 或 `.eh_frame` 时不注册握手及调用者片段。定位时也先检查边界和
明文发送字段，再读取候选缓存，缺少必要条件时不生成握手增强。

通过前提检查的握手及调用者片段与 read/write 签名一起注册到 ELF pattern cache，由现有
`memmem::Finder` 搜索，低内存模式共享分块页面。后续只读取缓存偏移并分析候选附近的指令。
离散的调用者候选也按现有 ELF 分块大小分组，同一窗口内处理完五种调用者片段后统一
释放映射页，避免不同片段重复加载同一窗口。使用五个有序偏移切片的游标推进，无需
合并或重新排序候选；Full 模式保持页面驻留。
证书候选验证及局部函数指令读取后也释放对应窗口，防止稀疏读取累积文件大页。

1. 握手片段为 `LDR xN,[x1]; MOV w8,#1`。共享搜索七字节公共后缀，命中后先核验
   LDR 的 x1 基址、偏移 0、紧随的 STRB w8 与同一缓冲寄存器的 CBZ，以及指令对齐，
   再通过 `.eh_frame_hdr` 二分查询所属函数。
   Grok 直接缓冲 ABI 使用八字节 `MOV w8,#1; STRB w8,[x0,#822]` 种子；再确认紧随
   其后的 `CBZ x1`。仅通过完整校验的命中进入函数候选预算。
2. 明文发送函数通过有预算的控制流汇合分析，提取 self 字节读取、与 1 比较和条件分支。
   字节读取与比较之间允许一条不覆盖该值及 self 基址的 64 位读取。
3. 握手候选局部验证入口 self 同字段写 1、第二参数提供可空缓存引用、空缓存返回以及
   非空缓存的循环和调用。字段偏移来自指令。
   可空缓存接受第二参数本身或第二参数指向的包装值；长度读取和判空之间允许一条
   保存缓存引用的 64 位 MOV，且不得覆盖长度。两个判空分支必须到达同一返回出口。
4. 调用者片段覆盖 `ADD x1,Rn,#imm; MOV x0,x23|x24; BL` 和
   `MOV x0,x23; ADD x1,x19,#imm; BL` 形状。前者用 ADD 的最后一字节加完整 MOV，
   后者用完整 MOV 加 ADD 的第一字节作为五字节种子。后者也会接受 Rn 低三位相同的
   寄存器作为候选。随后核验完整 ADD/BL 编码、指令对齐和实际调用目标。
   Grok 调用者使用 `MOV w8,#1; STRB w8,[x25|x28,#823]` 的两个完整八字节种子，
   再验证紧随的 BL。字段及对象关联仍由局部来源分析确认。
5. 仅对调用握手候选的指令执行局部来源分析，确认同一对象的另一个字节先被置 1。
   有效调用者的前置位字段必须一致，握手候选必须唯一。

种子用于筛选，命中不等于接受。ADD 立即数、状态字段和 BL 位移均由指令提取。
Grok 的严格种子包含已核验的状态偏移，减少短片段造成的离散窗口读取。
候选片段覆盖 Codex/Xiaoo/Grok 编译形状；其他编译形状需增加候选片段并实际验证。
没有独立的全代码 STRB/BL 枚举、全文件调用图或外部反汇编进程。

寄存器来源只包含未知、常量、入口参数及偏移、参数内存引用。分支来源不一致时置为未知；
调用使 caller-saved 寄存器失效。函数边界按 FDE 索引查询，不分配全量 FDE 表。

## 预算配置

以下环境变量在 detector 构造时读取一次，必须为正整数。前缀预算不得大于函数预算。

| 环境变量（前缀 `ACTRAIL_RUSTLS_HANDSHAKE_`） | 默认值 | 限制 |
|---|---:|---|
| `FUNCTION_INSTRUCTIONS` | 512 | 明文发送函数和通过前缀筛选的握手函数指令数 |
| `PREFIX_INSTRUCTIONS` | 64 | 握手候选首个控制转移之前的指令数 |
| `CANDIDATES` | 16 | 握手片段所属函数数量 |
| `MATCHING_CALLS` | 128 | 指向握手候选的调用数量 |
| `CALLER_INSTRUCTIONS` | 48 | 调用前最多回溯的指令数 |
| `DATAFLOW_STEPS` | 32768 | 本次定位的总分析步数 |

成功与拒绝存入现有 ELF named-address cache；键包含算法版本、发送入口和完整预算配置。
共享缓存使用原有二进制身份与文件 generation。未启用共享缓存时，结果随 ELF 视图释放。

## 接入边界

只有需要 native 身份的 aarch64 executable consumer 注册握手候选片段并执行增强：
`Direct`、`PlanOnly`，以及无 PT_INTERP 的 `Daemon`。叶候选只验证一次；selector 产生的
父级副本复用增强结果，保留诊断证据树。

`RustlsConnectionLayout` 接受完整 52/64、48/56、52/64-x22 和 52/64-stack160 明文入口对。
证书布局使用共用的八字节 Vec 读取及比较片段参与共享搜索，再局部验证析构结构。
RecordLayer 内联销毁与独立函数销毁分别核验完整指令形状；独立函数还验证两个 Box
的析构调用。证书偏移从已验证的读取指令提取。
Grok 1.0.70 的调用式 Vec 析构路径核验两个 Box 析构、前置可选 Vec 的销毁、证书元素
按 24 字节步进的析构循环及证书 Vec 的释放；各释放路径必须指向同一分配器，元素
析构必须调用已经验证的字节 Vec 释放函数。所有调用目标均从局部 BL/B 指令解析，
不依赖构建地址。辅助函数读取完成后释放扫描窗口。
缺少函数边界、局部结构无法证明、结果歧义、预算不足或证书布局未确认时，
保留已匹配的读写位点；全部验证通过后才设置身份 cookie 并追加握手位点。
0-RTT、服务端 half-RTT、无证书路径及被完全内联的握手入口不在已验证范围。
