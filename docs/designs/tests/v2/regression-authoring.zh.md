# V2 Regression 文档规范

每个 Regression case 的 `README.zh.md` 必须使用以下结构：

```text
# <测试名称>
# Quick Run
# 步骤摘要
# 手动测试
```

## Quick Run

必须包含：

- 从仓库根目录执行的单 case 命令；
- 测试依赖的外部条件；
- 测试目标的简短说明。

## 步骤摘要

按自动测试的真实顺序概括主要阶段，例如外部条件检查、AcTrail 启动、workload、
证据验证和清理。

## 手动测试

每一步必须使用：

```markdown
## 步骤x：要做什么

### 手动指令

可直接执行的操作。

### 预期结果

可以观察并判断的现象。
```

步骤编号必须连续。每个步骤必须同时具有“手动指令”和“预期结果”。

## 操作媒介

按测试目标选择最直接的操作方式：

1. 测试 Web UI 或浏览器交互时，优先写浏览器操作。
2. 测试 CLI、daemon、viewer 或本地进程时，使用 Bash。
3. 手动复现使用浏览器、自动脚本没有浏览器时：
   - 先写浏览器操作；
   - 标明自动脚本不执行浏览器步骤；
   - 提供对应接口的 `curl` 命令；
   - 说明页面现象与接口字段如何对应。

`curl` 只能验证接口数据，不能代替页面布局和交互验证。

## 内容要求

- 指令必须能从仓库根目录直接操作，不能只写“准备环境”或“检查结果”。
- 文档中的 workload 参数必须与自动测试一致。
- 必须说明如何取得本次测试的 marker 和 trace id。
- 必须给出验证 AcTrail 证据的实际操作，不能只检查 workload stdout。
- 需要等待 trace/action 时必须给出有上限的轮询。
- 必须包含清理步骤。
- 每一步的预期结果必须写明具体状态、字段、数量或可见现象。
- 必须明确外部条件不满足是 `SKIPPED`，AcTrail 失败是 `FAILED`。
- 文档不得包含凭据或敏感数据。

## 提交前检查

- `README.zh.md` 包含三个规定章节。
- 每个手动步骤都有指令和预期结果。
- Bash 和 `jq` 片段语法有效。
- 手动命令与自动测试一致。
- case 已加入 `test_all.py` 和 Regression README 索引。
