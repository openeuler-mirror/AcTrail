# AcTrail 能力概览

> 本文说明 AcTrail 针对常见安全问题提供的证据、控制和运行条件。

Trace 汇总一次受观测进程树的证据；行为摘要将底层活动组织为可查询的进程、文件、网络和 Agent 行为。

| 问题 | AcTrail 提供的证据或控制 | 重要条件 |
| --- | --- | --- |
| 某个 Agent 启动了哪些进程？ | 进程生命周期、父子关系、命令行、执行上下文和命令活动 | 启动观测在程序执行前建立采集上下文 |
| Agent 与哪些远端服务通信？ | 网络连接、远端地址、传输活动、HTTP 交互和服务类型 | 加密连接内容由 TLS 明文采集提供 |
| LLM 请求与响应是什么？ | 请求内容、响应内容、模型、服务方、工具调用和关联证据 | 内容由协议解析、采集容量和保留策略共同提供 |
| Agent 读取或修改了哪些文件？ | 文件路径、访问方式、读写活动、共享文件映射和批量读取摘要 | 文件采集提供路径与操作信息 |
| Agent 如何通过管道、本地套接字或标准输入输出协作？ | 通信双方、通道关系、数据方向和输入输出内容 | 内容采集与元数据采集分别提供正文和活动记录 |
| 能否限制文件或命令操作？ | fanotify 文件决策、seccomp 命令决策及审计证据 | 需要配置治理规则、失败决策和权限 |
| 能否导出到其他观测系统？ | trace JSON、OpenTelemetry Protocol（OTLP）JSON，以及可选实时 exporter 插件 | 导出内容受独立对外传输设置控制 |

AcTrail 将系统活动、传输内容和协议消息整理为进程、文件、LLM 与工具行为摘要。

运行方式取决于两个问题：工作负载能否由 AcTrail 启动，以及是否必须在 exec 前安装 TLS/seccomp 能力。需要启动前准备的场景使用 `actrailctl launch`；只观察已经运行的进程时可使用 `track-add`，但它无法追溯安装启动时能力。详见 [运行模型](runtime-model.md)。

需要按执行身份、传输证据、协议语义、治理结果和输出边界逐项核对时，可参阅[采集与观测清单](collection-observation-checklist.md)。
